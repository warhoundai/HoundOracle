# Campaign08: public contrastive evidence training

Baseline `e55a817`. This campaign continues with a new public dataset rather than repeatedly tuning exhausted FEVER diagnostics. No new cloud resources, API expenditure, public text/weight redistribution or production replacement is authorized or performed.

## Evidence source and rights

Read the original [VitaminC paper](https://aclanthology.org/2021.naacl-main.52/) including annotation methodology, article splits and contrastive evaluation; acquired author-hosted `tals/vitaminc` at pinned revision `be6febb761b0b2807687e61e0b5282e459df2fa0`. File sizes and SHA256 hashes are in `data-provenance.json`.

The paper describes70 native English annotators writing/reviewing claims against Wikipedia edits, with NEI used when explicit contradiction was not justified. It reports article-level splits consistent with FEVER for overlaps. This experiment independently checks selected partition overlaps instead of assuming those official splits suffice.

Data incorporates Wikipedia under applicable article terms / CC-BY-SA3.0. Upstream code is MIT, which does **not** relicense the dataset. Preserve attribution to Schuster, Fisch & Barzilay (NAACL2021), Wikipedia contributors and applicable FEVER sources. Only real revision cases are used; FEVER-derived synthetic pairs are excluded. Data permits commercial use subject to its terms; source text, token inputs and trained neural weights stay outside the Apache repository, and redistribution needs a separate compatibility review.

These are human **conditional claim/evidence labels** on historical, sometimes counterfactual passages. They do not certify current-world truth, retrieval quality, source independence, live citations, or Gemini superiority. Pretraining contamination and unrecognized entity aliases cannot be ruled out.

## Data isolation

Selected components globally connect normalized page, case ID, exact normalized claim and evidence span. Cross-official-split components are excluded. Evaluation excludes components touching all previously observed FEVER source pages/claims/spans. One complete revision case is selected per component, keeping contrastive evidence together.

- Training:1,600 real VitaminC pairs from548 components plus1,600 historical FEVER development examples.
- New validation:602 pairs /207 components.
- New calibration-fit:600 pairs /199 components.
- New calibration-risk:602 pairs /209 components.
- Locked test:600 pairs /212 components, unscored until a frozen candidate passes.

All selected partitions have zero normalized page/exact-claim/nonempty-span overlap. Hashes, IDs and exclusions are in `dataset-manifest.json`; no source text is redistributed here. Unlike the exhausted FEVER residual, these sets contain substantial YES/NO/MAYBE populations. Labels were never generated by Gemini.

## Controlled training and evaluation

One fixed epoch, seed1920, batch8, AdamW2e-5, weight decay.01, clip1, CPU2threads, max256 tokens. Training starts from the same pinned original MiniLM safe weights. No validation-based checkpoint selection, remote model code, calibration or test training labels. Final weights and ONNX stay local. Export requires dynamic-shape Torch/ONNX parity before benchmarking.

Controls: unchanged original encoder with frozen old head; original encoder with an equally supervised new mixture logistic head; prior FEVER-only encoder/frozen head; and new mixed-data encoder with the same head protocol. All compared at a matched256-token envelope. This is not an exact replay of the stable512-token default workflow. Default engine behavior remains unchanged; explicit shorter token limits cannot exceed reviewed manifest limits, and calibration fingerprints include the effective limit.

Calibration maps are fitted only on the dedicated fit partition; temperature/logistic/isotonic selection uses validation Brier score. A separate risk partition checks selected components. Four model/head configurations use Bonferroni alpha.05/4 for one-sided case-any-error bounds, plus empirical row-risk bootstrap diagnostics and minimum selected sample sizes. These are population-specific conditional estimates, not truth probabilities or guarantees under arbitrary shift. Minimum confidence remains.80, with.85 routing diagnostics reported separately. Raw accuracy and complete-case accuracy prevent an abstention-only apparent win.

Training and baseline scoring run concurrently to use the available CPU. Their recorded timings are therefore **not** a paired inference-speed comparison. Local and cloud cost fields remain separate; zero new cloud charges does not mean zero development or infrastructure cost.

## Reproduction

Use `acquire_vitaminc.py`, `prepare_vitaminc_campaign.py`, `tokenize_vitaminc_training.py`, then `train_vitaminc_encoder.py` in the isolated CPU training environment. Run dynamic parity helpers before `score_vitaminc.py contrastive`. The original and prior-encoder score paths establish controls. `fit_vitaminc_evaluators.py` validates complete ID coverage before fitting/calibration; incomplete traces cannot silently qualify. Locked scoring requires a qualification artifact.

## First training result and continued execution

The full400-step/3,200-pair epoch completed in1,094.09 seconds. Safe-weight SHA256 is `4be90152ff0ae33ff663ce9c5b01598ca3d678677957624b7c2a3b1c021388af`. Training loss moved from.903 for the first25 steps to.553 for the last25; this is optimization evidence, not generalization proof. Dynamic ONNX parity passed ten batch/length cases up to256 tokens.

On the new602-pair validation set, raw accuracy was60.13% with the frozen old head,61.63% with the original encoder/new equally supervised head,62.62% with the FEVER-only trained model, and**71.43% with mixed-data training**. Complete contrastive-case accuracy improved from the strongest prior reference35.27% to45.41%.

The mixed model still failed the conservative confidence gate:114/131 selected risk components were fully correct, with Bonferroni-adjusted lower correctness bound.78997 versus the required.80. The empirical row-risk bootstrap upper bound was.12112, a different estimand; it was not substituted to force qualification. Locked test remains unscored. First-round calibrated coverage is zero for all configurations because their qualification gates fail; raw accuracy/case accuracy and selected-risk counts remain visible.

The user explicitly instructed continuation. Round2 adds unused public revision cases with replay and continues from the first safe checkpoint, keeping architecture, objective, batch size and learning rate fixed. AdamW state is explicitly restarted. It compares against the parent encoder with both a frozen and an equally supervised replay-mixture head. Validation and fit partitions are reused as development evidence; the risk partition is new. Before any round2 scores, risk power was expanded to1,804 pairs/620 independent components without changing thresholds. Original risk files remain immutable; hashes and the power amendment are recorded in `round-2/`. The original locked600 remains sealed until a configuration qualifies and selection is frozen.
