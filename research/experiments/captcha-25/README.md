# Local open-source text-CAPTCHA recognition

Hypothesis: a local pretrained OCR backend can recognize bounded text-image CAPTCHAs without outsourcing images. User asked for an automatic or open-source CAPTCHA solver. Implemented Tesseract and pinned ddddocr1.6.1 adapters, CLI, optional authenticated REST/MCP tools and an optional container profile. Interactive Google CAPTCHA solving remains unsupported; do not conflate text recognition with browser attestation or site acceptance.

Licensing: original ddddocr repository README/LICENSE and PyPI distribution metadata were inspected. Both declare MIT, including a distribution-level license alongside packaged models; separate model training-data provenance was not established. The wheel SHA256 was checked before installing locally. Model hashes are retained in upstream.json; no model weights/source were copied into Oracle. Tesseract is the simpler Apache-2.0 default. No paid solver API or generative model was called.

Protocol: seed2501,40 synthetic5-character images,8 per family: digits, uppercase, mixed, noisy-uppercase, rotated-mixed. DejaVu Sans Bold40px, font hash in result records. Caller-specified alphabet is fixed by family, not derived per image from its label. Exact case-sensitive equality measures recognition. Backend cold process launch and model load are included in timings. Images/labels are generated by benchmarks/captcha_text.py, not Google/Gemini. This is development/stress data; there is no locked independent real-world qualification set.

First comparison (baseline-results.json): Tesseract26/40, ddddocr15/40. Inspection found ddddocr's alphabet filtering could drop lowercased predictions in uppercase-only fields. Candidate fix retains OCR alphanumerics then changes case only when the caller's declared alphabet allows the opposite case exclusively. Mixed-case input is left case-sensitive. Second comparison (case-projection-results.json): Tesseract26/40, ddddocr25/40. Paired descriptive bootstrap for ddddocr development improvement:25percentage points,95% interval12.5–40points. This is not independent generalization evidence. All errors remain in records. Default selected Tesseract for its simplicity and measured cold latency; the1/40 difference does not establish broad superiority. Keep ddddocr experimental.

Second-run measured P50/P95: Tesseract0.3052/0.4242seconds; ddddocr0.3750/0.5410seconds. Environment versions in comparison.json. Reproduce using `.venv/bin/python benchmarks/captcha_text.py --output /tmp/captcha-results.json`. Tesseract binary/English data and the captcha extra must be installed. Different package versions, font or hardware change results.

Safety/correctness regressions cover untrusted input bounds, subprocess credential stripping, unsupported interactive types, no claimed server acceptance, process-group timeout cleanup, actual malformed-image rejection, opt-in authenticated REST and MCP execution. Both native backends were exercised on a generated PNG with sockets disabled in the worker. No actual Google image-grid, hCaptcha or third-party submission was tested. Captcha image recognition is separate from Oracle's factual-verification accuracy.

No paid cloud resources were created. Container configuration validation passed; the new image was not fully built due workspace disk constraints. No public release. Next useful qualification needs independently labeled representative text CAPTCHAs and an explicit acceptance protocol. Do not promote a99% claim from this experiment.

Final verification:184 tests pass on Python3.11/3.12; lint, wheel and Compose configuration pass. Source hashes and fixture checks in validation.json.
