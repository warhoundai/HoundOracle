# Evidence understanding follow-up

The central bottleneck remains semantic correctness and qualified coverage, not
raw local arithmetic speed. Three candidate families are isolated from production:

| Candidate | Reused development result | Decision |
|---|---|---|
| Two-encoder standardized logistic stack | Raw77.29% vs77.78%; fewer correct accepted answers | Reject |
| Generic DeBERTa-v3-base | Raw63.29% vs77.78% | Reject |
| Supervised DeBERTa adaptation | See campaign29 completed assessment | Gate before fresh risk/test |
| Single-passage context selection | Raw77.78% vs contaminated top3 context65.22% | Retain scoped research only |

The last comparison recovers lost accuracy; it does not beat the stable
supplied-evidence baseline. Candidate confidence remains unqualified. Numerical
runtime differences between separate machines are not paired speed measurements.
No new Gemini calls, source-citation audit or whole-agent cost study are represented
by these local semantic screens. Native ONNX/PyTorch kernels already use compiled
code; an additional C++ wrapper has no demonstrated remedy for these errors.

Before any general API promotion, the compiler must support the evaluated claims,
retrieval must preserve temporal/entity context and contradictions, extracted spans
must receive independent citation review, and a frozen decision policy must qualify
on independent source/event components. A99% score on tuned development data does
not establish that qualification. The joint gate in `strict_goal.py` additionally
prevents high selective precision from hiding incorrect abstentions.
